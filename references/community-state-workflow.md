# Community v2.0：导演版剧本、状态与局部返修

## 从原文到镜头

保留三层信息：SOURCE是原始事实与台词；DIRECTOR_SCRIPT仅补动作与表演可见过程；EXECUTION是每段八模块提示词。把导演补充与原文分开，防止补表演时改剧情。新补的反应只能由该角色已经获得的信息触发。

先给情绪曲线和空间锚点，再建分段表。每镜回答：当前状态是什么，发生什么刺激，哪一动作可见，结果变成什么，为什么现在切。每段只承载一个主要戏剧变化。

## 轻量账本格式

读取 `examples/state-ledger.json` 作为可运行样例。顶层：`schema_version: 1`、`model_max_seconds`与`segments`。每段：`id`、整数`duration`、`entry`、`shots`与`exit`。

每份状态有：

- `scene`：固定场景ID，不含屏幕左右。
- `characters`：按稳定角色ID记录 `position`（固定场景锚点）、`posture`、`body_direction`、`eyeline`（场景目标）、`left_hand`、`right_hand`、`action_phase`、`emotion`与`knowledge`（非重复事实ID列表）。
- `props`：按稳定道具ID记录 `holder`、`hand`、`location`、`orientation`与`functional_state`。无人持有时holder与hand都填null；手持时holder必须存在且hand为left/right/both。

每镜：`id`、`start`、`end`、非空`event`（可见变化及触发），以及`changes`列表。每次变化包含`path`、`before`、`after`；path为已有角色或道具的字段，例如 `characters.A.emotion`。严格从当前值before变成after。情绪和知识变化也需要落到可见反应或实际听见的信息。未变化字段不重复事件。

场景坐标与机位坐标分开：角色可始终坐“桌左椅”，正反打的画面左右可以变化。不能因为屏幕构图变化在账本里擅自换座。

## 状态交接

段内：entry → 按时间排序的镜头changes → exit。跨段：exit(N) = entry(N+1)。首镜移动和交接在下一段首镜执行，不能用“首动作会改变”豁免入口不一致。

当前beta采用固定角色/道具集合，不支持凭空增删实体或自动跨场切换。新人物出现、道具进入和明确时间跳跃应先建立新场景账本并由导演写清过渡；不可伪造状态连续通过审计。画外人物和暂不入画道具继续在该场景账本中记录，不因镜头看不见就删除。

每段提示词完整重建entry；退出模块完整表达exit。首镜不强制复刻上一段末镜，也不为“镜头刷新”强制换机位导致越轴。状态一致是底线，镜头变化取决于戏剧与剪辑需要。

## 返修路由

| 观察到的问题 | 回到哪一层 | 修改后复核 |
|---|---|---|
| 漏词、错词、重复起句 | SOURCE / 声音事件 | 本段完整原文与邻接声桥 |
| 坐姿变跪姿、换座、换手 | entry / 镜头表述 | 上段exit、本段entry与exit |
| 动作先后顺序错误 | DIRECTOR_SCRIPT / event | 起势、重叠窗口、接触、相位 |
| 画外人物误入镜 | 镜头可见性 | 实际入画名单、前后景与反打 |
| 角色提前知道秘密 | knowledge / 反应触发 | 信息出现镜头及后续反应 |
| 眼线反向或越轴 | 固定场景锚点 / 摄影机 | 相邻镜头与可见换边路径 |

在保持原台词与既定落点的前提下，给出修复段完整提示词；不只给零碎补丁。用户明确要求查看诊断时可展示账本错误，但执行Prompt不堆内部字段。

## 验证范围

`state_ledger_audit.py`验证字段类型、时间码闭合、每镜不超过4秒、状态变化可回放和跨段入口一致。它不能理解自然语言动作是否真实、不检查视频、也不自动判断knowledge变化是否有剧情依据。导演必须将账本、原文、提示词三者对照。Community轻量账本不包含私有Pro的表演签名、完整道具语义状态机或声音身份系统。
